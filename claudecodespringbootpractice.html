用 Claude Code 完整开发一个 Spring Boot 项目，实录与复盘

之前写过 Codex 接入 DeepSeek 的教程，这次换个主角：Claude Code。我拿它从头开发一个完整的 Spring Boot 服务，从空目录到能跑、带单元测试，全程只改 Prompt、不手写业务代码，看它到底行不行。

本文把整个过程如实记录下来，包括每一步的 Prompt、生成的产物、踩过的坑，以及最后的效率对比。

一、项目背景与目标

为了公平测试，我选了一个 Java 开发者最熟悉的场景，而不是花哨的 AI 应用：

项目：内部任务管理服务（TaskService）

  • 用户注册 / 登录（JWT 鉴权）
  • 任务 CRUD（增删改查、分页、状态流转）
  • 定时提醒（到期的任务触发通知）
  • 操作日志（记录关键操作）

技术栈：Spring Boot 3 + MyBatis-Plus + MySQL + JWT。

选这个项目的原因很简单：越贴近日常，越能看出 AI 的真实水平，也越有参考价值。

二、准备工作

环境：本机已装 Node、MySQL，Claude Code CLI 已配置好模型。

我建了一个空目录，然后写下第一条指令：

用 Spring Boot 3 + MyBatis-Plus + MySQL + JWT 搭建一个任务管理服务。
先给出项目整体结构和技术选型说明，确认后再开始生成代码。

注意最后那句”先给方案再动手”——这是用 AI 写代码最重要的习惯之一，避免它一上来就甩一堆你根本不想要的文件。

三、第一轮：生成项目骨架

Claude Code 给出了目录结构和核心依赖，并询问了我几个关键点（是否用 Lombok、分页插件、包名等）。我确认后，它直接生成了：

task-service/
├── pom.xml
├── src/main/java/com/example/taskservice/
│   ├── TaskServiceApplication.java
│   ├── config/          # 配置类
│   ├── controller/      # 接口层
│   ├── entity/          # 实体类
│   ├── mapper/          # MyBatis-Plus Mapper
│   ├── service/         # 业务层
│   └── util/            # 工具类（JWT 等）
└── src/main/resources/
    └── application.yml

这一轮我只做了两件事：确认技术选型、审核目录结构。骨架阶段不要让它直接写业务代码，结构错了后面全乱。

四、第二轮：核心业务代码

确认骨架后，我开始让它按模块生成。这一轮的策略是”一次只做一个模块“：

现在实现用户模块：用户注册、登录、JWT 生成与校验。
要求：
1. 密码 BCrypt 加密存储
2. JWT 里带 userId 和 username
3. 登录接口返回 token 和用户基本信息
4. 用户表字段：id, username, password, nickname, create_time

它依次生成了 UserController、UserService、UserMapper、JWT 工具类和对应的建表 SQL。

我审核时发现两个小问题：

  • 注册时没有校验用户名是否重复（让它在 Service 里补了一个判断）；
  • 异常没有统一处理（让它加了一个全局异常处理器）。
请补充：
1. 注册时校验用户名唯一，重复则抛出业务异常
2. 增加 @RestControllerAdvice 全局异常处理器，统一返回 {code, message, data}

修完这两点，用户模块收工。

五、第三轮：任务模块与定时提醒

任务模块直接复用用户模块的模式，生成速度明显变快：

实现任务模块：任务的增删改查、分页、状态流转（待办→进行中→完成）。
要求：
1. 支持按状态、关键字筛选
2. 分页返回，返回格式 {code, message, data: {records, total}}
3. 只有任务创建人才能修改自己的任务
4. 删除使用逻辑删除（MyBatis-Plus @TableLogic）

生成后我在本地跑起来，用 curl 验证了接口。这一步很关键：AI 生成的代码必须真的跑一遍才算数，不能只看它”写得像是对的”。

定时提醒部分稍微费了点劲——它默认用了 Spring 的 @Scheduled，我要求改成”启动时从数据库加载未完成任务，按到期时间调度”：

定时提醒改成：服务启动时从数据库加载所有未完成任务，到期时间在接下来 10 分钟内的任务触发提醒，触发后标记为已提醒。
使用 Spring @Scheduled 每 1 分钟扫描一次。

这轮它理解了”启动加载 + 周期扫描”的模型，改得比较干净。

六、第四轮：单元测试

我让它补了核心模块的单元测试：

为 UserService 和 TaskService 编写单元测试，使用 Mockito，不依赖数据库。
覆盖：
1. 注册成功 / 用户名重复
2. 登录成功 / 密码错误
3. 任务创建、状态流转、越权修改

生成后执行 mvn test，第一次跑挂了几个用例，报错基本都是 Mockito 用法问题。我把报错贴回去：

下面测试失败，报错信息如下，请修复：
[错误信息粘贴]

它定位后修好了测试桩（stub）的写法，第二次全部通过。

七、调试与修复实录

过程中遇到的几个真实问题，记录一下：

问题 现象 修复方式
日期格式 接口返回 2026-08-03T10:30:00 而不是预期格式 让它加全局 Jackson 日期格式配置
MyBatis-Plus 分页不生效 返回 total=0，实际有数据 提醒它配置分页插件 PaginationInnerInterceptor
JWT 密钥写死 代码里硬编码密钥 让它移到配置文件并用环境变量注入

这三个问题都符合一个规律：不是 AI 不会写，而是”默认配置”和”你的环境”不匹配。AI 不知道你的数据库字符集、你的分页需求、你的部署方式，这些上下文必须由你来补。

八、效果统计

以下数据以我这次开发为例，具体数字建议换成你实际跑的记录。

项目 数据
总耗时 约 3 个晚上，每天 2 小时左右
代码量 约 2500 行（含测试）
单元测试 28 个用例，覆盖核心模块
我手写的代码 0 行业务代码，只改过几处配置
我花的时间 60% 在写 Prompt 和审核，40% 在跑起来联调

如果是传统方式，这个规模的项目从零搭起来，加上写测试和修各种环境问题，我预估至少 2~3 个工作日。用 Claude Code 后，真正省掉的是”生成骨架、写 CRUD、写测试”这类体力活，而审核和联调的时间没有减少。

九、复盘：Claude Code 的边界在哪

用完一个完整项目，我对它的能力边界有了比较清晰的认知：

它擅长的：

  • 项目骨架、CRUD、单测生成——效率极高；
  • 修报错——把错误信息贴回去，定位又快又准；
  • 重复模式化的代码——几乎不用操心。

它不擅长的：

  • 模糊需求——“做个任务管理”它做不出来，你得拆到足够细；
  • 架构权衡——选 Redis 还是本地缓存、要不要引入消息队列，这种决策它给不了你；
  • 跨系统一致性——比如和前端约定字段、和老系统对齐格式，它完全无感。

我的角色定位：

  • 需求拆解者：把模糊需求拆成它能执行的明确指令；
  • 审查者：它写的每段代码都要过一遍，尤其涉及安全和权限；
  • 联调者：真正跑起来、和上下游对接，还是得人来。

一句话总结：Claude Code 是”执行者”而不是”设计师”，你把设计想清楚，它能以极高的效率帮你落地。

十、总结

  • 用 Claude Code 完整开发一个 Spring Boot 项目完全可行，CRUD、单测、修 bug 这些活它能干得很漂亮。
  • 效率提升是实打实的，但省的是体力活，不是思考。需求拆解和代码审查还是你的核心工作。
  • 最有价值的工作方式：一次一个模块、明确约束、生成后必须真的跑起来验证。
  • AI 编程时代，会”拆需求、会审查、会联调”的工程师，效率是别人的几倍。
