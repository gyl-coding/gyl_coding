Codex 接入 DeepSeek V4

DeepSeek 官方宣布 Codex 已支持接入 DeepSeek 模型，deepseek-v4-flash 率先开放，deepseek-v4-pro 之后也会陆续支持。也就是说，在 Codex 里直接使用 DeepSeek 模型，从官方层面正式打通了。

先简单交代一下背景：Codex 是 OpenAI 推出的 AI 编程助手，底层通过 Responses API 与模型通信；而 DeepSeek API 原生兼容这套协议，所以不需要任何中间层转换，配置完成后就能把 Codex 当作 DeepSeek 的客户端来使用。

更省心的是，Codex 的各个客户端形态（Codex CLI、ChatGPT 桌面端、VS Code 的 Codex 插件）共用同一份本地配置文件，只要配置一次，所有入口都能调用 DeepSeek 模型，不用挨个重复设置。

一、前置准备

在开始之前，需要先准备好两样东西：

（1）装好 Codex 客户端

安装 Codex CLI 或 ChatGPT 桌面端，并且至少成功启动过一次。这样本地才会自动生成 ~/.codex 配置目录，后面的脚本和手动配置才有落点。

（2）申请 DeepSeek API Key

前往 DeepSeek 开放平台 申请 API Key，通常以 sk- 开头。

小提示：API Key 相当于账号的钥匙，务必妥善保管，不要提交到公开仓库，也不要随意转发给他人。

二、方式一：一键脚本接入（推荐）

DeepSeek 官方提供了一键配置脚本，会自动完成备份、写入模型目录、修改主配置等全部工作，推荐优先使用这种方式。

1. 执行配置脚本

macOS / Linux 在终端执行：

bash <(curl -fsSL https://cdn.deepseek.com/api-docs/codex-deepseek-setup.sh)

Windows 在 PowerShell 中执行：

irm https://cdn.deepseek.com/api-docs/codex-deepseek-setup-en.ps1 | iex

2. 按菜单选择模型

脚本运行后会弹出菜单，首次使用选择 1（修改 Codex 配置），再选择要使用的模型，比如 deepseek-v4-flash：

之后想恢复默认配置也很简单，重新执行脚本，选择菜单第 3 项即可一键还原。

3. 输入 API Key

接下来脚本会提示输入 API Key。如果电脑上已经配置了 DEEPSEEK_API_KEY 环境变量，脚本会自动读取，跳过手动输入：

4. 重启客户端

配置完成后，重启 ChatGPT 桌面端（或重新打开 Codex CLI），就能在模型列表里看到 DeepSeek 模型了：

脚本到底自动做了什么？

  • 备份原配置：把 ~/.codex/config.toml 备份到 ~/.codex/backup-deepseek/，随时可以还原。
  • 写入模型目录：向 ~/.codex/models.json 写入 DeepSeek 模型的元数据（上下文窗口长度、支持的推理强度档位、工具调用格式等），让 Codex 能像调用内置模型一样调用 DeepSeek。
  • 修改主配置：只改写必要字段，新增 [model_providers.deepseek] 配置段；原有的 MCP 服务器、项目信任级别等配置都会保留，若发现冲突字段会自动删除并打印删除原因。
  • 语法校验：写入前先校验 config.toml / models.json 的合法性，校验不通过就中止，不会破坏原有文件。

这套脚本可以反复执行，切换模型、恢复默认配置都靠它，属于“一次接入、长期受益”的类型。

三、方式二：手动编辑配置文件

如果你更喜欢自己掌控细节，也可以手动配置，只需要编辑两个文件：~/.codex/models.json 和 ~/.codex/config.toml。

1、模型目录文件 ~/.codex/models.json

这个文件用来向 Codex 声明 DeepSeek 模型的元数据。官方完整文件里，deepseek-v4-flash 与 deepseek-v4-pro 各是一个模型对象，关键字段如下（以 flash 为例）：

{
  "models": [
    {
      "slug": "deepseek-v4-flash",
      "prefer_websockets": false,
      "support_verbosity": true,
      "default_verbosity": "low",
      "apply_patch_tool_type": "freeform",
      "web_search_tool_type": "text",
      "input_modalities": ["text"],
      "supports_image_detail_original": false,
      "truncation_policy": { "mode": "tokens", "limit": 10000 },
      "supports_parallel_tool_calls": true,
      "multi_agent_version": "v2",
      "use_responses_lite": false,
      "context_window": 1048576,
      "max_context_window": 1048576,
      "effective_context_window_percent": 95,
      "display_name": "DeepSeek-V4-Flash",
      "default_reasoning_level": "high",
      "supported_reasoning_levels": ["low", "high", "max"],
      "shell_type": "shell_command",
      "visibility": "list",
      "minimal_client_version": "0.144.0",
      "supported_in_api": true,
      "priority": 1
    }
  ]
}

说明：官方完整文件里还包含 model_messages 中的一大段系统提示词模板（instructions_template / base_instructions），内容由 Codex 内部维护、篇幅较长，不建议手动抄写。直接用方式一的脚本生成，可以保证与官方一致、不出差错。

2、Codex 配置文件 ~/.codex/config.toml

在 ~/.codex/config.toml 中新增（或修改）以下内容：

model = "deepseek-v4-flash"
model_provider = "deepseek"
preferred_auth_method = "apikey"
forced_login_method = "api"
model_reasoning_effort = "high"
model_catalog_json = "~/.codex/models.json"

[model_providers.deepseek]
name = "deepseek"
base_url = "https://api.deepseek.com/"
wire_api = "responses"
experimental_bearer_token = "你的 DeepSeek API Key"

字段说明：

字段 作用
model 默认使用的模型
model_provider 使用的模型提供方 id，对应 [model_providers.<id>] 配置段
preferred_auth_method / forced_login_method 设为使用 API Key 认证，跳过 ChatGPT 账号登录流程
model_reasoning_effort 推理强度（low / high / max），值越高思考越深入、回答质量越高，耗时也越长
model_catalog_json 自定义模型目录文件路径，Codex 从这里读取模型元数据
name 模型提供方显示名称
base_url DeepSeek API 接口地址
wire_api 通信协议，responses 表示使用 Responses API
experimental_bearer_token 你的 DeepSeek API Key，直接写在配置文件里

几点提醒：

  • 如果已有 config.toml，注意不要重复定义 model、model_provider 等字段，避免与已有配置冲突。
  • 之前配置过其它模型提供方的话，建议先把原文件备份一份再动手。
  • 手动方式适合进阶玩家，日常使用还是推荐方式一，省心又不易出错。

四、实测：用 Codex 生成数据可视化仪表盘

配置完成后，直接开测。我用 Codex 尝试生成一个数据可视化仪表盘页面，提示词如下：

请帮我生成一个数据可视化仪表盘的单页面 HTML 文件（dashboard.html）。

要求：
1. 通过 CDN 方式引入 ECharts（例如 https://cdn.jsdelivr.net/npm/echarts），不使用任何本地依赖或构建工具，我要能直接双击这个 html 文件在浏览器里打开查看效果。
2. 页面包含至少 4 个图表：
   - 一个折线图：展示某产品近 12 个月的销售趋势（数据可以是模拟的）
   - 一个柱状图：展示 5 个地区的销售额对比
   - 一个饼图：展示各产品品类的销售占比
   - 一个仪表盘（gauge）：展示当月目标完成率
3. 整体使用响应式布局（CSS Grid 或 Flexbox），在桌面和手机宽度下都要能正常显示，不能错位。
4. 支持深色/浅色主题一键切换，切换时所有图表配色也要跟着联动变化。
5. 图表加载时要有淡入或缩放的进场动画。
6. 顶部要有一个模拟的筛选栏（时间范围选择、地区下拉框），选择后图表数据能相应联动刷新（数据变化可以是前端模拟的）。

请直接生成完整可运行的 HTML 文件内容。

五、总结

  • 接入方式上：一键脚本适合绝大多数用户，自动备份、自动校验、随时可还原；手动配置则适合想深入了解配置细节的进阶玩家。
  • 配置一次，Codex CLI、ChatGPT 桌面端、VS Code 插件三端通用。
  • 别忘了保护好自己的 API Key，推荐用环境变量管理，避免明文写入配置文件或仓库。
