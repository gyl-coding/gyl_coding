6年 Java 工程师转型 AI Agent 开发，我是怎么学的

先说下我的背景：Java 后端写了 6 年，主要做 Spring Boot 微服务。近两年 AI Agent 越来越火，我也从”围观”到”上手”，现在已经能用 Claude Code 辅助日常开发，也能自己搭简单的 Agent 应用。

这篇文章把我自己的学习路径整理出来。网上写 AI 学习路线的大多是 Python 或算法背景，站在 Java 后端视角的不多，所以我把每一步”怎么和已有经验衔接”也写上了，希望对同样背景的同学有帮助。

一、先说结论：这不是转行，是叠加

很多 Java 工程师一听到 AI Agent 就焦虑，觉得自己要被”转型”了。我的看法恰恰相反：这不是转行，是叠加。

AI Agent 工程化，本质上还是工程问题——系统设计、接口、日志、测试、部署、监控，这些正是后端工程师天天在干的事。模型只是多了一个不太稳定的”组件”，而怎么管理一个不稳定的组件，恰好是后端最擅长的。

所以别把心态放在”我要从头学一门新语言”，而是放在”怎么让我熟悉的系统长出 AI 能力“。带着这个心态，下面这条路会好走很多。

二、阶段一：补大模型基础（第 1~2 周）

目标：搞清楚大模型是什么、怎么调用，脑子里有 token、上下文、temperature 这些基本概念。

这一阶段不用深究原理，够用就行：

概念 一句话理解
token 模型处理文本的最小单位，计费按它来
上下文窗口 模型一次最多能”看到”的 token 数，超了会截断
temperature 控制输出的随机性，值越高越发散
system / user prompt 系统提示词放规则，用户提示词放输入
function calling 让模型自己决定”要不要调用某个函数”，Agent 的地基

动手任务：注册一个 API（OpenAI / DeepSeek 都行），写一个最朴素的调用脚本。用 Python 还是 Java 都无所谓，这一阶段重在”亲手打通一次模型调用”。

我的建议：别沉迷刷科普视频。直接调 API 调一周，比看十篇原理文章有用得多。

三、阶段二：Prompt 与上下文工程（第 3~4 周）

目标：从”调对话”进化到”调 Agent”。

这一阶段把 Prompt 从”写一段话”升级成”写一份规范”。重点学三件事：

  1. 结构化 Prompt：角色、任务、约束、输出格式分开写，而不是一段话糊在一起。
  2. system 和 user 的分工：规则放 system，数据放 user。
  3. 上下文管理：模型记不住太多东西，要学会”按需给信息”。

这块我单独写过一篇《AI Agent 开发 prompt 提示词怎么写》，里面的八段式结构就是这一阶段的实践总结，可以直接参考。

练习场：用 Claude Code 写 Java 代码。你一边让 AI 干活，一边观察它怎么理解你的需求——这是理解”模型视角”最好的方式，比背一万条 prompt 技巧都有用。

四、阶段三：Function Calling / Tool Use（第 5~6 周）

目标：让模型”长出手脚”，这是从”聊天机器人”到”Agent”的分水岭。

前两个阶段模型只会”说话”，这一阶段它开始”干活”。核心就一件事：给模型注册函数，模型自己判断什么时候调用。

{
  "type": "function",
  "function": {
    "name": "get_weather",
    "description": "查询指定城市的天气",
    "parameters": {
      "type": "object",
      "properties": {
        "city": { "type": "string", "description": "城市名" }
      },
      "required": ["city"]
    }
  }
}

这段 JSON 就是”给模型看的函数签名”。模型看到任务需要天气，就会返回一个”我要调用 get_weather(city=杭州)”的请求，你的代码再去真正执行它。

动手任务：用官方 API 实现一个”能查天气、能算账的小 Agent”。跑通一次”模型决策 → 代码执行 → 结果回填”的闭环，你对 Agent 的理解会上一个台阶。

五、阶段四：RAG 与记忆（第 7~8 周）

目标：解决”模型不知道你业务数据”的问题。

模型的知识是训练时固定的，它不认识你数据库里的表、你文档里的业务规则。RAG（检索增强生成）就是给它”开卷考试”：先检索相关文档，再带着文档回答问题。

这一阶段需要了解：向量化（Embedding）、向量数据库、检索流程。但我的建议是：

先跑通，别陷进去。 RAG 调优（切分策略、召回率、重排序）是个深坑，第一版能”答得上话”就行，优化留到有真实业务再回来。

动手任务：挑一份你手头的内部技术文档，做一个”文档问答 Agent”。

六、阶段五：Agent 框架与编排（第 9~12 周）

目标：从”一个函数调用”到”多步骤工作流”。

到这一步，你要开始考虑：一个任务涉及多个步骤、多个工具、中途还会失败，怎么编排？

这一阶段要理解几个概念：

概念 理解
Workflow vs Agent 流程是”写死的步骤”，Agent 是”模型自己决定步骤”
ReAct 模式 思考 → 行动 → 观察 → 再思考 的循环
多智能体 多个 Agent 分工协作，一个写代码、一个 review
LangChain / LangGraph Python 生态的事实标准，理解思想即可，不必精通

Java 党的重点：把注意力放在 Spring AI 和 LangChain4j 上。它们把 Agent 能力封装成 Spring 风格，你可以把”AI 能力”当普通 Bean 一样注入到业务系统里。这对于我们这种”要在现有微服务里加 AI 功能”的场景，比学 Python 重写一套实用得多。

七、阶段六：工程化落地（长期）

前面都是”做出来”，这一阶段是”做稳定“，也是后端工程师最能发挥优势的地方：

  • 可观测性：Agent 怎么调的？哪一步失败了？token 花了多少？——详见我写的《Agent 也是”系统”》。
  • 评测（Evals）：怎么判断”这次 Prompt 改好了还是改坏了”，要有一组固定用例做回归。
  • 安全：Prompt Injection（提示词注入），Agent 读外部内容时被”劫持”的风险。
  • 成本：token 是钱，上下文越大越贵，要养成”按需给信息”的习惯。

八、Java 工程师的独特优势

学完上面这些，你会发现自己的 Java 背景不但不是包袱，反而是三个优势：

  1. 工程化思维：类型系统、单元测试、CI/CD、日志监控——这些 AI 工程化里最难补的课，你早就练了六年。
  2. 现成的业务和数据：你手里有真实系统、真实数据。AI Agent 落地最大的瓶颈不是算法，是”能不能接进真实业务”，这恰恰是你的主场。
  3. 稀缺性：目前 Java 生态的 Agent 实战内容远少于 Python，你先学以致用就是先发优势。

九、我的时间线与几条经验

阶段 时间 产出
大模型基础 第 1~2 周 跑通一次 API 调用
Prompt / 上下文 第 3~4 周 自己的 Prompt 规范
Function Calling 第 5~6 周 一个工具调用 Demo
RAG 与记忆 第 7~8 周 一个文档问答 Agent
框架与编排 第 9~12 周 一个多步骤工作流
工程化落地 长期 真实项目 + 监控 + 评测

几条经验：

  • 少看多写：收藏夹吃灰的文章永远比写完的 Demo 多。每个阶段必须有”动手产出”才进入下一个。
  • 先跑通再优化：第一版能用就行，别在第一步就追求完美。
  • 不会的当场问 AI：我学新框架时习惯开着 Claude Code，不懂的直接问，比翻文档快。
  • 边学边记录：每解决一个问题，就写进博客。这既是复习，也是在积累自己的影响力。

十、推荐资源清单

  • 官方文档（最权威，优先看）：Anthropic、OpenAI、DeepSeek 的 API 与 Agent 文档。
  • Java 方向：Spring AI 官方文档、LangChain4j 官方文档——这是 Java 党的主阵地。
  • 动手项目：GitHub 上搜 mcp-server、spring-ai-examples，直接看别人怎么写的。
  • 我的博客相关文章：《AI Agent 开发 prompt 提示词怎么写》《Agent 也是”系统”》《从 Spring Boot 的视角理解 MCP》。

总结

  • AI Agent 开发对 Java 工程师不是转行，是叠加：你已有的工程能力全是资产。
  • 学习路径可以压缩成一句话：会调模型 → 会写 Prompt → 会让模型调工具 → 会喂记忆 → 会编排 → 会做稳定。
  • 每天 1~2 小时，3 个月能上手，6 个月能落地一个真实项目。关键是每个阶段都动手产出，别只看不练。

祝大家都能让手里这 6 年的 Java 经验，在 AI 时代继续升值。
